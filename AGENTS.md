# AGENTS.md — инструкции по репозиторию

Репозиторий: `VladimirPolozov/VladimirPolozov.github.io` (ветка `main`, GitHub Pages).
Сайт — сборник аккордов церковных песен: docsify на статике без сборки.

## Что это

- `index.html` — точка входа: подключает `tools/transpose-core.js`, `tools/transpose.js`, `tools/share.js`, `tools/menu.js`, `tools/search.js`, `tools/set.js` **до** CDN docsify@4, настраивает `window.$docsify` (сайдбар, `breaks: true`, `routerMode: 'history'`). Штатный плагин поиска docsify не подключается — поиск свой.
- Один файл `songs/<id>.md` — одна песня. `id` — число (`1.md` … `238.md`), оно же короткий URL: `/songs/42` (без `.md`). Назначается один раз по алфавиту текущих имён; новые песни получают следующий свободный номер, существующие не сдвигаются. Старые длинные ссылки не поддерживаются (alias-карты нет).
- 238 песен, 78 исполнителей (`artists/`), 6 категорий (`categories/`).
- `set.md` — справка/страница конструктора сетов `/set` (см. `tools/set.js`).

## Структура

- `songs/*.md` — песни. В начале: frontmatter `key:`, затем `# Название`, затем блок сведений (`> **…:**`), затем аккорды и слова.
- `artists/*.md` + `artists/index.md` — страницы исполнителей (заголовок `# Имя`, список песен со ссылками).
- `categories/*.md` + `categories/index.md` — страницы категорий.
- `_sidebar.md` — сайдбар docsify (главная, исполнители, категории, песни).
- `tools/` — скрипты (см. ниже).
- `search-index.json` — индекс поиска (заголовки + тексты песен), генерируется `tools/build_search_index.js`.
- `audio/` — редкие mp3 (до ~25 МБ), подключаются `[Слушать](audio/файл.mp3)`.
- `channel_export/` — сырые экспорты Telegram, в git не коммитятся (`.gitignore`).

## Маршрутизация (чистые адреса)

- `routerMode: 'history'` — адреса без `#`: `/songs/42`, `/artists/bethel-music`, `/set?song_id=1&key=A`.
- GitHub Pages не отдаёт несуществующие пути: на `/songs/42` отвечает `404.html`, который кладёт полный URL в `sessionStorage.redirect` и уходит на `/`. `index.html` при загрузке возвращает путь в адресную строку через `history.replaceState` — до старта docsify, поэтому страница открывается сразу по чистому адресу.
- Внутренние ссылки — без `.md`. Старые ссылки с `#` и длинные слаги не поддерживаются (alias-карты нет).
- `basePath` не задаём — docsify по умолчанию читает корень (`basePath: ''`).

## Формат песни

```markdown
---
key: A
---
<!-- tg: msg <id> | <дата> -->

# Название песни

> **Исполнитель:** [Bethel Music](/artists/bethel-music)
> **Категория:** [Поклонение](/categories/poklonenie), [Прославление](/categories/proslavlenie)
> **Оригинальное название:** Waymaker
> **Тональность:** A
> **Размер:** 6/8
> **Темп:** 118
```

- Поле «Категория» должно идти **до** «Тональность» (транспонирование затрагивает блок от «Тональность»).
- Аккорды — строки вида `D | A | E | F#m |`.
- Части песен (Куплет, Припев, Вступление, Проигрыш, Окончание, Предприпев, Тэг, Поворот, Бридж, Рэп) — русские, жирным `**…**`, без двоеточия, цифра в конец («Куплет 1»), с большой буквы. См. `tools/normalize_sections.js` (был удалён после применения).

## Категории

Буквы разметки: **P** — прославление, **W** — поклонение, **M** — средний темп, **C** — детские, **O** — другое, **J** — еврейские. Песня может быть в нескольких категориях.

Порядок отображения: Поклонение, Прославление, Средний темп, Детские, Еврейские, Другое.

## Скрипты

- `tools/build_categories.py` — **актуальный**. Читает поле `**Категория:**` из песен, пересобирает `categories/*.md` и `categories/index.md`. Запуск: `python tools/build_categories.py`.
- `tools/transpose-core.js` — ядро транспонирования (аккорды, тональности, DOM). `transposeKeyTextNodes` — транспонирует только узлы от «Тональность»/«Key:», чтобы не задеть «Исполнитель:».
- `tools/transpose.js` — плагин docsify: кнопки −/0/+, средняя показывает текущую тональность буквой (`G#`, `A`, `Bbm`…) и сбрасывает при клике; выбранная тональность пишется в `?key=` в адресе (без localStorage), переход на другую песню сбрасывает транспонирование (если в URL нет `?key=`); при открытии ссылки с `?key=` песня сразу транспонируется в неё.
- `tools/share.js` — плагин docsify: кнопка «поделиться» в правом верхнем углу карточки песни (не `fixed`), копирует текущий `location.href` (вместе с `?key=`) через Clipboard API с фолбэком на `execCommand`; тон плавающей подсказкой «Ссылка скопирована».
- `tools/menu.js` — плагин docsify: неоморфный гамбургер (`position:fixed`, **левый нижний** угол), переключает класс `close` на `body` — штатное состояние docsify. Крестик, когда сайдбар свёрнут. На ширине ≤768px (`body.close` = панель выехала) кнопка прячется (`opacity:0`), а при выборе песни панель закрывается и кнопка возвращается. Штатная кнопка docsify `button.sidebar-toggle` скрыта в `index.html`: она внутри `.sidebar`, у которого в закрытом виде есть `transform`, а transform предка делает его containing block для `position:fixed` — кнопка уехала бы за экран (и в теме vue она тоже снизу слева). Штатное автозакрытие docsify работает только при `clientWidth <= 600` на момент загрузки, поэтому закрытие панели при выборе песни продублировано явно (`classList.remove('close')`, не `toggle` — чтобы не конфликтовать с обработчиком docsify).
- `tools/build_search_index.js` — **актуальный**. Пересобирает `search-index.json`: заголовок (`# `) + только строки текста; строки аккордов отсекает `isChordLine` из `transpose-core.js`, служебные строки (frontmatter, `<!-- tg: … -->`, блок `>`, `##`, `**Куплет**`, аннотации вида `Куплет ( … )`) выкидывает. Запускать **после каждой правки/добавления песен** (как `build_categories.py`), иначе поиск не найдёт новые песни. Индекс детерминированный (без даты), вывод — одна строка JSON.
- `tools/search.js` — плагин docsify: поиск **над карточкой** (не в сайдбаре, не `sticky` — `.content` у docsify `position:absolute`, поэтому липнуть не к чему), ленивая загрузка `search-index.json` по первому фокусу, выпадающий список: название + одна строка с совпадением, если совпадение не в названии; кнопка-крестик очистки, ↑/↓/Enter/Esc, подсветка совпадений. Ранжирование: сначала совпадение в названии, потом позиция совпадения в тексте. Клики внутри поиска гасятся через `stopPropagation`, иначе обработчик docsify на `body` открывал бы сайдбар на ширине ≤600px. Индекс берётся по абсолютному `/search-index.json` (со страниц вроде `/songs/42` относительный путь ушёл бы в `/songs/`); выбор результата — `history.pushState` + `popstate`, без решётки.
- `tools/set.js` — плагин docsify: страница `/set?song_id=…&key=…&…`. В `beforeEach` асинхронно собирает markdown (docsify ждёт Promise только от хука с двумя аргументами, поэтому нужна callback-форма `function (content, next) { … next(md); }`), грузит `songs/<id>.md` и ставит каждую песню в свою тональность; `key` привязывается к непосредственно предшествующему `song_id` (песня без `key` — в исходной). Кнопки общей транспозиции сдвигают весь сет визуально, URL при этом не меняется. Отсутствующая песня даёт `Песня <id> — не найдена`.
- `tools/test_transpose.js` — тесты корпуса (`node tools/test_transpose.js`): прогонять перед пушем, если менялся `transpose-core.js` или логика определения/сдвига аккордов. Для чисто визуальных/CSS-правок в `transpose.js` (без изменения разбора аккордов) тест можно пропустить — он проверяет, что не-аккордовые строки не меняются.
- `tools/song_meta.py`, `tools/build.py`, `tools/extract_meta.py`, `tools/migrate.py`, `tools/export_to_md.py`, `tools/gen_sidebar.py` — **устаревший Python-конвейер** (README о нём устарел). Песни правятся вручную/разовыми скриптами; `build.py` перезапишет блоки сведений (уберёт ссылки на исполнителей, «Оригинальное название», «Размер», «Темп», «Категория») — не запускать. В `song_meta.py` / `extract_meta.py` остались старые слаги в виде ключей — они больше не совпадают с именами файлов.

## Конвенции и история решений

- Транспонирование сбрасывается в 0 при каждом переходе на другую песню (localStorage больше не используется).
- Тональность — в YAML-frontmatter `key:`; DOM-парсинг blockquote — fallback (`captureBaseKey` берёт текст после «Тональность»).
- «Оригинал» в метаданных → «Оригинальное название»; «3/4», «6/8» → «Размер»; bpm (обычно 60–148) → «Темп».
- Имя исполнителя в сведениях — ссылка на страницу `/artists/<slug>`; мульти-исполнители — через запятую, каждый со ссылкой.
- Категория в сведениях — ссылка на `/categories/<slug>`.
- Ссылки в сайдбаре/категориях: песни — `/songs/<id>` (без `.md`), исполнители/категории — `/artists/<slug>` / `/categories/<slug>`.
- Разовые скрипты удаляются из репозитория до коммита.
- Коммиты на русском. Пуш в `main` деплоит GitHub Pages.
- В консоли PowerShell кириллица в выводе git/Select-String искажается — для чтения UTF-8 лучше использовать node-скрипты.

## Типичные задачи

- **Добавить категорию песне**: вставить/поправить строку `> **Категория:** […](/categories/…)`, затем `python tools/build_categories.py`.
- **Проверить перед пушем** (если трогали логику аккордов): `node tools/test_transpose.js`.
